# 实时盯盘（boardwatch）

「实时盯盘」是 Lizzieyzy/KataGo 便携版的窗口实时盯盘工具：你选择任意一个包含围棋棋盘的
窗口（对弈软件、网页直播、录像回放……），工具每隔几秒自动截取该窗口画面，识别其中的
棋盘，增量推演出着法，并在自己的界面上实时摆盘；开启 AI 面板后，还会随棋局进展调用
KataGo 给出实时胜率与形势（归属）分析。

识别核心复用 `screenshot2board/recognizer.py`（自动 19/13/9 路识别），规则推演复用
`netplay/netplay.py` 的纯 Python 规则引擎（提子/禁自杀/禁全同形）。

## 快速上手

1. 双击根目录 **`实时盯盘.bat`** 启动（或 `python boardwatch\boardwatch.py`）。
2. 在顶部下拉框选择要盯盘的窗口（显示"标题 [进程名] (宽x高)"），可点「刷新窗口列表」重新枚举。
3. **找不到目标窗口？点「点选窗口」**：按下按钮后 5 秒内直接单击目标窗口（点棋盘区域即可）。
   适合枚举不到的窗口，如微信小程序里的「腾讯围棋」（挂在 WeChatAppEx.exe 进程上、
   常以无标题窗口形式出现）。列表里无标题窗口会以 `（无标题）进程名` 标注。
4. 设置刷新间隔（默认 5 秒，最小 2 秒），点击「开始盯盘」。
5. 左侧即为实时摆盘；右侧显示窗口缩略图（识别成功时用绿色框标出识别到的棋盘四角，
   便于确认对准）与状态、日志。
6. 看完后点「停止」；「保存 SGF」把当前局面存为棋谱（`boardwatch/games/时间戳.sgf`），
   「在 Lizzieyzy 打开复盘」会先保存再调用 Lizzieyzy 打开复盘。

## AI 面板（KataGo 实时胜率/归属）

- 勾选顶部「AI 面板 (KataGo)」开启（默认关）。开启后，每当盯盘检测到棋盘变化，会在
  盯盘线程内调用 `engine_18b/katago.exe`（loadsgf 方案）做一次 `kata-raw-nn` 分析，
  显示：
  - **黑方胜率** = (1 - whiteWin) × 100%
  - **目数差(黑-白)** = -sum(ownership)
  - **归属热图**：叠加在左侧棋盘上，蓝色 = 白方地域、红色 = 黑方地域（阈值 ±0.4），
    随棋局进展动态更新。
- 引擎启动失败或分析超时会静默降级（不影响盯盘本身），日志中提示一次。
- 引擎进程在退出程序时自动关闭。

## 追踪模式说明

每次截帧识别后，工具把观测到的棋盘当作唯一真值，与上一帧比对：

| 模式 | 何时发生 | 处理 |
| --- | --- | --- |
| 初始化 (init) | 首帧，或棋盘路数变化（19/13/9 切换） | 直接按观测盘面摆盘同步 |
| 无变化 (same) | 与上一帧完全一致 | 跳过（最常见） |
| 落子 (move) | 恰好 1 个空点出现新子（允许同时有提子消失）；先用规则引擎落子，再整盘逐点核对（含提子效果），核对通过才接受 | 手数 +1，画最后一手标记 |
| 悔棋 (undo) | 无新子、有子消失，且消失点正好是追踪的最后一手；撤销后整盘核对通过 | 手数 -1 |
| 重新同步 (resync) | 其余情况：一帧内多点同时变化（盯盘间隔内下了不止一手）、落子/撤销核对失败、轮次错乱（如同一方连下）等 | 丢弃推演历史，按观测盘面重新摆盘；重新同步次数 +1 |

注意：

- 进入重新同步后，推演历史被清空；之后导出的 SGF 会改用"摆子谱"（AB/AW 直接摆当前
  局面），而不是逐手谱。
- 撤销"一手提子"在画面上表现为被提诸子同时重现（多点变化），因此会走重新同步而不是
  悔棋模式——这是设计取舍：观测真值优先。
- 摆盘同步后的先行方按黑白子数推断（黑多则白先，否则黑先）；猜错时下一手会核对失败并
  自动重新同步一次，随后自愈。

## SGF 与 Lizzieyzy 复盘

- 无重新同步且有落子历史 → 逐手谱（`;B[..]` / `;W[..]`）。
- 否则 → 摆子谱 `(;GM[1]FF[4]CA[UTF-8]SZ[n]KM[..]AB[..]AW[..])`。
- 「在 Lizzieyzy 打开复盘」先保存 SGF 再用 `jre/java17/bin/javaw.exe -jar
  lizzie-yzy2.5.3-shaded.jar <sgf>` 打开（分离进程启动）。

## 后台窗口支持（与 ok-ww / ok-nte 同类能力）

本工具与 GitHub 上的 ok 系列后台工具（[ok-wuthering-waves](https://github.com/ok-oldking/ok-wuthering-waves)、
[ok-nte](https://github.com/BnanZ0/ok-nte)，均基于 [ok-script](https://github.com/ok-oldking/ok-script) 框架）
采用同一条技术路线：**Win32 PrintWindow（PW_RENDERFULLCONTENT）**——窗口在后台被其他
窗口完全遮挡时照样能截到完整画面，无需置顶或激活（ok-script 的 BitBlt 方案核心即此调用）。
已实测：目标窗口被置顶窗口完全盖住时，截屏识别结果与窗口可见时完全一致。

- **未最小化的后台窗口**：直接支持，无需任何设置。
- **最小化的窗口**：任何截屏 API 都拿不到有效画面（ok 系列的做法是自动还原窗口）。
  本工具提供同样能力：勾选「**最小化时自动还原窗口**」（默认开），盯盘检测到窗口
  最小化时会自动把它还原并继续盯盘；取消勾选则跳帧等待。
- ok-script 还有 Windows Graphics Capture（WGC）方案用于对抗 PrintWindow 黑帧的
  特殊窗口（需自研 COM 互操作，依赖重）；本工具在黑帧时回退屏幕截取，覆盖绝大多数
  围棋相关窗口（对弈客户端/浏览器/看图软件），未引入该重依赖。

## 同步到 Lizzieyzy（复盘界面实时更新）

勾选顶部「**同步到 Lizzieyzy**」后，盯盘识别到的局面会实时推进 Lizzieyzy
的复盘界面——胜率图、候选点、形势判断全部照常工作，无需手动导入。两条通道：

| 通道 | 触发方式 | 特点 |
| --- | --- | --- |
| **增量协议**（推荐） | 在 Lizzieyzy 中按一次 **Alt+O**（菜单 同步→棋盘同步工具(Alt+O)） | 复用 Lizzieyzy 内置棋盘同步通道，逐手增量摆盘，**不抢焦点、零打扰** |
| **剪贴板** | 无需任何设置，自动启用 | 每次棋面变化自动向 Lizzieyzy 粘贴导入，Lizzieyzy 会被短暂置前 |

- **轮次自动对齐**：单张截图无法判断该谁落子，但连续同步可以——工具按
  交替落子原则推断当前轮次（Lizzieyzy 每摆一子翻转换子方，其状态完全可
  追踪），不一致时自动发一次 pass 翻正，形势判断不再踩轮次错误。已实测：
  pass 后引擎立即切换 `kata-analyze B/W`，胜率相应大幅变化。
- **回退/重同步轮次同样精确**：检测到悔棋、画面突变（多点同变）或棋子
  换色时，自动清盘整帧重摆；剪贴板通道的摆子局面会合成为合法交替棋谱
  （黑白交替+虚着补位），轮次由手数奇偶自然正确——两条通道的轮次都精确。
- **不弹命令行黑框**：所有后台子进程（剪贴板回退、端口扫描）均以无窗口
  方式运行；剪贴板被其他程序短暂占用时自动重试。
- **采样间隔实时可调**：盯盘过程中拖动间隔即可生效（快棋调小、慢棋调大，
  最小 2 秒）。
- 增量通道的原理：本工具接管了 Lizzieyzy 棋盘同步的启动器
  （`readboard\readboard.bat` 转发同步端口，原文件备份为
  `readboard.bat.orig`，原引擎 `readboard.exe` 备份为 `readboard.exe.bak`），
  以相同的行协议把局面推给 Lizzieyzy 的 `ReadBoard` 服务端。
- 若勾选后状态栏提示"未发现同步通道"，在 Lizzieyzy 里按一次 Alt+O 即可。
- 对局结束后正常「保存 SGF / 在 Lizzieyzy 打开复盘」即可深度分析。
- 自动端到端验证脚本：`python boardwatch\e2e_lizzie_sync.py`
  （会启动 Lizzieyzy 并推送测试局面，建议桌面空闲时运行）。

## 已知局限

- **回退截屏需要窗口可见**：极少数硬件加速窗口（某些浏览器/播放器）用 PrintWindow
  可能截出黑帧，此时回退为屏幕截取（PIL ImageGrab），要求该窗口在屏幕上可见且不被
  完全遮挡；被其他窗口盖住的区域会被一并截入。
- **窗口最小化**：截不到有效画面（无效残帧会被过滤并跳帧）；勾选「最小化时自动还原
  窗口」可自动还原继续盯盘。窗口从枚举中消失或句柄失效时，盯盘会自动停止并提示。
- **识别失败会跳过该帧**：画面中没有完整棋盘、棋盘被大幅遮挡或切换了动画画面时，该帧
  被跳过，下一帧重试；失败/恢复只各记录一条日志，不刷屏。
- **以管理员运行的窗口**（如某些游戏客户端）：低权限进程读取其标题会被系统拦截，
  窗口可能显示为「（无标题）」，且 PrintWindow 会被拒——此时回退屏幕截取（要求窗口
  可见），或右键 `实时盯盘.bat`「以管理员身份运行」后再使用。
- **盯盘间隔内多于一手** 会触发重新同步（棋面仍正确，但推演历史断开）。想减少重新同步
  请调小间隔。
- **棋盘识别**依赖截图分辨率：格距过小（窗口过小）或非常规配色主题可能识别不出。
- AI 分析的贴目取 SGF 中的 KM（默认 7.5，中国规则）。

## 运行测试

```
python boardwatch\test_boardwatch.py
```

覆盖：追踪器合成序列（init/same/move/提子/undo/resync/轮次错乱/换盘面）、SGF 生成与
sgfmill 回读、窗口枚举与真实窗口截屏识别（端到端）、KataGo 真实引擎 loadsgf 分析、GUI
冒烟。输出全 ASCII，汇总 PASS/FAIL/SKIP，失败时退出码非 0。

## 文件

- `boardwatch/boardwatch.py` — 主程序（单文件）
- `boardwatch/test_boardwatch.py` — 回归测试
- `实时盯盘.bat` — 启动器（优先 pythonw，无窗口控制台）
- `boardwatch/games/` — 保存的棋谱
- `boardwatch/tmp/` — 分析用临时 SGF（运行时自动生成）
